OpsRoom — first-run setup

Everything the deployment needs, once. It will not ask for your organization's name — that is the product's question, answered after you log in.

OpsRoom — restore

This rebuilds an instance from its backup onto this machine. It will not ask for an administrator account or a domain package — those come back from the backup, with every other setting, exactly as they were.

Product download

Checked against the registry the moment you submit — a typo is a field error here, not a stalled install later. The download itself happens as the first step of the install, on the progress page.

Administrator

The platform admin — the account that creates the organization. No seeded alice; no password in the repo.

Backups (Cloudflare R2, or any S3-compatible bucket)

Object Read & Write, scoped to the bucket.

Recovery keys — two places, or nothing

Both are shown once, after install, to put in a password manager. The last instance was lost because each existed in one place.

File storage (a SECOND bucket, with its own token)

Where the files people upload are kept. It must be a different bucket with a different token from your backups: the backup token may read this one, never the other way round, so a mistake on either side cannot reach the other. auto is right for Cloudflare R2; AWS wants a real region; MinIO ignores it.

The backup to restore

A timestamp like 20260913T025705Z, as listed in your bucket. Empty means the newest one there.

Both from your password manager. The passphrase opens the database dumps; the age key opens the instance's own configuration, which is the half that makes the restored databases usable. Neither is in the backup — that is deliberate, and it is why the bucket alone is not enough to read your instance.

Domain package

The domain package this instance runs, pinned at install like the product version. Leave the default unless your vendor gave you another; none for a blank instance.
